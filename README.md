# SupplyTrace / Цепочка поставок

SupplyTrace — учебный Django-проект / PoC для анализа участия компаний в публичных закупках по ИНН. Это не production-система.

Проект собирает данные из открытых источников, показывает карточку компании, таблицу закупок за последний год, частоту участия юрлиц, интерактивный граф связей и HTML-отчёт.

## Что считается «тендером» в проекте

В интерфейсе мы говорим «тендеры и закупки», но внутри проекта работаем с наблюдаемыми публичными записями о закупках и заключённых контрактах. Для каждой такой записи показываются:

- номер / идентификатор;
- дата заключения;
- дата исполнения, если источник её раскрыл;
- предмет;
- сумма;
- заказчик и его ИНН;
- поставщик / победитель и его ИНН, если они раскрыты;
- статус: открытая или закрытая закупка;
- ссылка на источник.

Закрытые закупки не отбрасываются: если победитель не раскрыт, интерфейс явно показывает `Закрытая закупка`, `Победитель не раскрыт` и `ИНН поставщика отсутствует`.

## Источники данных

Основной рабочий сценарий — ручное обновление из публичных источников:

- ЕИС `zakupki.gov.ru`;
- Портал поставщиков `zakupki.mos.ru`;
- ТЭК-Торг `tektorg.ru` через официальный SOAP API процедур.

Для `sberbank-ast.ru` добавлен best-effort HTML parser открытых реестров. По умолчанию он отключён: площадка может блокировать автоматические запросы защитой ЭТП и не публикует стабильный CSV/JSON API без авторизации. Если включить `SBERBANK_AST_SYNC_ENABLED=True`, приложение попробует разобрать публичный HTML, но не будет обходить капчи, авторизацию или антибот-защиту.

Также в списке провайдеров есть заготовки для `bicotender.ru` и `rts-tender.ru`. По умолчанию они отключены: на момент доработки не использовался агрессивный HTML-scraping, потому что для этих площадок не подключён стабильный публичный CSV/JSON API без авторизации, капчи или ограничений. Их можно включать только после добавления официального API/выгрузки в отдельный сервисный модуль.

Реквизиты карточки компании могут уточняться через DaData, если задан `DADATA_TOKEN`.

Проект не хранит публичные реестры целиком. В локальной базе остаются только компании, найденные закупки/контракты и журнал обновлений по тем ИНН, которые пользователь уже открывал или обновлял.

Дата исполнения есть не у всех записей и не у всех источников. Для ЕИС она подхватывается, когда приходит в CSV-выгрузке; для остальных источников поле остаётся необязательным.

Интеграции оформлены как провайдеры публичных источников. Новый источник стоит подключать отдельным сервисным модулем только если у него есть стабильная публичная CSV/JSON-выгрузка или API. Проект не должен обходить капчи, авторизацию, антибот-защиту или ограничения сайтов.

Автоматический live-sync зависит от доступности внешних источников. Если источник временно недоступен или возвращает неожиданный формат, приложение показывает уже сохранённые данные и фиксирует предупреждение, а не роняет страницу.

## Кэширование и приватность

Динамические страницы с ИНН, контрактами, статистикой, графом, отчётами, историей и JSON-ответами отдаются с `no-store/no-cache/must-revalidate`. Static-файлы CSS/JS обслуживаются обычным образом. Проект не использует `localStorage` для хранения ИНН, контрактов, графа или ответов API.

Локальная SQLite-база больше не рассчитана на бесконечное хранение бизнес-данных: параметр `SUPPLYTRACE_LOCAL_DATA_TTL_HOURS` задаёт, через сколько часов удаляются локально сохранённые компании без связей, контракты/закупки, история поиска и журнал синхронизации. По умолчанию — `24` часа. Значение `0` делает хранение максимально коротким, отрицательное значение отключает автоочистку. Очистку можно запустить вручную командой `manage.py purge_local_data`.

## Что умеет приложение

- искать компанию по ИНН;
- подтягивать свежие публичные данные по кнопке;
- показывать тендеры и закупки за последний год;
- выбирать видимые колонки в таблице закупок на стороне браузера;
- отдельно считать открытые и закрытые закупки;
- показывать, где победитель известен, а где не раскрыт;
- строить частоту участия компаний в закупках и контрактах;
- рисовать интерактивный граф `компания → закупка → победитель`;
- скачивать HTML-отчёт по компании;
- импортировать демонстрационные CSV без обязательных новых полей.

## Граф и таблицы

Граф строится через `vis-network` и сохраняет ограничение топ-контрагентов, чтобы большая выборка не превращалась в нечитаемую схему. Узлы можно двигать мышкой; работают drag, zoom и pan. При наведении на узлы и связи показываются подсказки с ролью участника, ИНН, суммой, датой, предметом закупки, статусом и источником, если он известен.

Таблица закупок отображается обычным HTML и остаётся читаемой без JavaScript. Если JavaScript включён, появляется блок `Настройка колонок`: выбор работает на стороне клиента и не сохраняет ИНН, контракты, граф или ответы API в `localStorage`.

## Быстрый запуск на Windows

Из корня проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Открыть:

```text
http://127.0.0.1:8000/
```

Если окружение уже создано, обычно достаточно:

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

## Быстрый запуск на Linux

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py runserver
```

## Настройки

Создайте `.env` из `.env.example`.

Основные параметры:

```env
ZAKUPKI_SYNC_ENABLED=True
ZAKUPKI_MOS_SYNC_ENABLED=True
ZAKUPKI_CONTRACTS_LIMIT=100
ZAKUPKI_CONTRACT_LOOKBACK_DAYS=365
ZAKUPKI_TIMEOUT=25
ZAKUPKI_USER_AGENT=SupplyTrace/1.0
SUPPLYTRACE_LOCAL_DATA_TTL_HOURS=24
TEKTORG_SYNC_ENABLED=True
TEKTORG_TIMEOUT=25
TEKTORG_SECTION_CODES=
SBERBANK_AST_SYNC_ENABLED=False
SBERBANK_AST_TIMEOUT=25
SBERBANK_AST_REGISTRY_URLS=
BICOTENDER_SYNC_ENABLED=False
RTS_TENDER_SYNC_ENABLED=False
DADATA_TOKEN=
```

`DADATA_TOKEN` необязателен. Если токена нет и реквизиты не удалось получить из закупок, приложение создаст минимальную карточку вида `Компания с ИНН ...`.

`TEKTORG_SECTION_CODES` можно оставить пустым: тогда используются рабочие публичные секции по умолчанию (`mirea_44`, `mirea_223`, `44fz`, `zakupki`). Для другой организации можно указать свои секции через запятую, например `44fz,zakupki,transneft`.

`SBERBANK_AST_REGISTRY_URLS` можно оставить пустым: тогда проверяются основные публичные реестры `utp.sberbank-ast.ru` из секций `SB` и `Trade`. Если площадка вернёт страницу защиты вместо HTML-реестра, источник зафиксирует предупреждение и продолжит работу приложения без обхода блокировки.

## Демо-данные

Для локальной демонстрации без зависимости от доступности внешних сайтов можно импортировать два набора:

```powershell
.\.venv\Scripts\python.exe manage.py import_contracts_csv data\import\contracts_demo.csv
.\.venv\Scripts\python.exe manage.py import_contracts_csv data\import\contracts_eis_demo_mirea_30.csv
```

Linux:

```bash
./.venv/bin/python manage.py import_contracts_csv data/import/contracts_demo.csv
./.venv/bin/python manage.py import_contracts_csv data/import/contracts_eis_demo_mirea_30.csv
```

Колонка `execution_date` в CSV необязательна. Старые CSV без неё продолжают импортироваться.

После импорта удобно открыть:

```text
http://127.0.0.1:8000/company/7729040491/
```

## Обновление из публичных источников

Обычное открытие карточки не делает сетевой запрос к реестрам. Это специально: страница остаётся быстрой и не показывает технические ошибки, если внешний источник временно недоступен.

Чтобы получить свежие данные, используйте кнопку `Найти данные в публичных источниках` или `Обновить данные` в карточке компании.

Для прямой проверки ЕИС можно запустить:

```powershell
.\.venv\Scripts\python.exe manage.py sync_zakupki_contracts 7729040491 --limit 20
```

После ручной синхронизации сохраняются дата обновления, итог и статистика по источникам; они отображаются в карточке компании и HTML-отчёте.
